# pipeline/ — зона разработчика A

Пайплайн данных: от архивов NASA FIRMS до единого гармонизированного ряда. Метод и метрики — `docs/methodology.md`.
Как получить готовые данные, не пересчитывая всё, — `data/README.md`.

## Запуск с нуля

```bash
python -m venv .venv
.venv/Scripts/pip install -e pipeline     # Linux/macOS: .venv/bin/pip
```

| Шаг | Команда | Результат | Время |
| --- | --- | --- | --- |
| 0. Загрузка архивов | `python pipeline/00_download_archives.py` | `data/raw/*.zip` (48 файлов, 9,3 ГБ) | ~1 ч |
| 1. Единая схема | `python pipeline/01_to_parquet.py data/raw/*.zip` | `data/points/<сенсор>_<год>.parquet` (7,1 ГБ) | ~20 мин |
| 2. Гармонизация | `python pipeline/02_harmonize.py` | `data/harmonized/*` | ~1 мин |
| 3. 2026 год через API | `python pipeline/03_fetch_2026_api.py` (нужен `FIRMS_MAP_KEY` в `.env`) | `data/raw/api_2026/` | 1,5–2,5 ч, упирается в лимит ключа |
| 4. 2026 → Parquet | `python pipeline/04_api_to_parquet.py`, затем снова шаг 2 | `data/points/*_2026.parquet` | ~2 мин |

- Шаг 1 запускать **одним процессом**: большие годы VIIRS (≈20 млн точек) требуют ~9 ГБ RAM.
- Шаги 0 и 3 можно перезапускать: готовые файлы пропускаются, недокачанные докачиваются.
  Две копии одного шага одновременно не запускать — они испортят файлы друг друга.

## Отличия от исходного плана

- Сетка 0,25° × месяц, а не 0,1° × день: для календаря по месяцам этого достаточно, и коэффициенты устойчивее.
  Дневную сетку 0,1° можно добавить в `02_harmonize.py`, если её потребует API.
- Постоянные источники: в архивах уже есть поле `type` (1 — вулканы, 2 — статичные, 3 — морские), фильтруем по нему.
  Для NRT-данных 2026 года без `type` маска строится из архива (шаг 4).
- Выходы лежат в `data/harmonized/`, а не в корне `data/` (список файлов — в `data/README.md`).
